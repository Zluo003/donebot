## 验证与发布约束

遵循 `docs/verification/README.md`。只用临时 home/data、合成用户和隔离网关。每批运行相应行为测试，并记录命令、结果及 fixture 日志；单元测试不替代工作流和真实 Linux 隔离验证。

基线须覆盖网关鉴权、媒体异步与幂等、价格、思考分离、设备、Cloud、更新，以及备份恢复。最后覆盖 Owner/Admin/Member/另一团队/未加入者、两个本机节点和 Cloud、撤权、取消、断线重启、计费、旧数据库和旧客户端。

每批单独提交。新增团队能力默认关闭。不上生产网关；不创建付费实例或使用真实用户资料。真实 Linux 容器、Windows、手机及在线升级的未执行项目须明确记录，不能以模拟测试代替。

上线顺序：兼容数据库变更 → 用户部署网关 → Cloud worker/运行镜像 → 客户端 → 核对能力后开启团队。回滚先关功能并恢复兼容版本，不删除团队数据或降级数据库。默认验证包为 arm64 未签名 DMG，正式发版另行指定。
